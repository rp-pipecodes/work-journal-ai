# The OS schedules Task Alerts

> The Complete deferral below is superseded by ADR-0035, which ships Complete
> as the Alert's one action. Scheduling, reconciliation and permission policy
> are unchanged, and Snooze remains deferred.

Timed Open Tasks are registered through macOS `UNUserNotificationCenter` with calendar triggers, so delivery does not depend on Work Journal still running and no remote push service or network is involved. Tauri's desktop notification plugin sends immediately and ignores its scheduling field, so it cannot meet this contract; the native scheduler is exposed through the existing platform seam instead. Only the one Open Task Occurrence is registered at a time—completion or recurrence edits cancel its request and register the successor—so pending OS state has the same cardinality as the domain. An Alert presents the full Task Description with sound even while Work Journal is active, leaving privacy previews and sound suppression to macOS; daylight-saving gaps move to the first valid instant and overlaps fire only once. The database remains authoritative across the non-atomic OS boundary: a failed registration never rolls back a Task, and future Alerts are reconciled on launch, wake, permission restoration, and schedule changes without replaying past alerts. Permission is requested only when the first timed Task is saved; refusal never blocks that Task, and Settings reports the denial and directs the user to macOS System Settings because the app cannot force or repeat the system prompt. Alerts only open the relevant Task—Complete and Snooze actions are deferred. Rejected: an in-process timer, which dies with the app; treating notification registration as if it shared the database transaction; the Tauri notification plugin, which cannot durably schedule future desktop delivery; and remote push, which breaks the local-only promise for a job macOS already owns.
