# Tasks are first-class work commitments

Tasks are work-focused records beside Notes, not a kind or state of Note: Notes recover work that happened, while Tasks hold work commitments and retain their completion. Tasks deliberately have no Project or category, completing one never silently creates a Note, and Tasks live in their own prospective view rather than inside retrospective Note History. This keeps simple commitments such as “email person X at Client Y” intact as free text rather than forcing them into the journal's day and Project filing model.

Rejected: treating a Task as a Note state or History filter, filing Tasks under Projects or categories, and automatically turning completed Tasks into Notes. Each would couple prospective work to a retrospective journal whose day and Project semantics mean something different.
